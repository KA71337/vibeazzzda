## Объём проверки

Проверены каталог, карточка товара и галерея для каталога из `data/products.json`, включая:

- товар с несколькими изображениями: **#2 Rolik Lescaul** (10 изображений);
- товар с одним изображением: **#3 Elektron Skuter XM-1**;

- компоновка desktop/mobile по responsive-классам и meta viewport;
- соответствие товар → массив изображений и доступность файлов.

Изображения, файлы каталога и связи товар → фото не изменялись.

## Найденные и исправленные безопасные дефекты

1. **Кадрирование товара.** Карточка и главное изображение использовали `object-cover`, из-за чего несquare-фото могли обрезать товар. Для основных товарных изображений применён `object-contain` с безопасным внутренним отступом; миниатюры сохранены с `object-cover`, поскольку это навигационные превью фиксированного размера.
2. **Нет fallback.** Прямой доступ к `p.images[0]` не защищал UI от пустого массива или сетевой/файловой ошибки. Добавлен общий `ProductImage`, показывающий нейтральный placeholder «Şəkil mövcud deyil» при отсутствии пути или `onError`; контент не подменяется другим товарным изображением.
3. **Галерея и доступность.** Кнопки миниатюр получили `aria-label` и `aria-pressed`; ключ учитывает индекс и устойчив к потенциальным повторным путям.
4. **Mobile overflow.** Для колонок detail добавлены `min-w-0`, для длинных названий/описаний — `break-words`; вертикальные отступы уменьшены на узком viewport. Лента миниатюр остаётся горизонтально прокручиваемой.
5. **Responsive image sizing.** Главное фото получило явный `sizes="(max-width:1024px) 100vw, 50vw"`; карточки уже имели responsive `sizes`.

Изменённые файлы:

- `src/components/product-image.tsx` — новый безопасный renderer/fallback;
- `src/components/product-card.tsx` — renderer и полное отображение товара без crop;
- `src/components/product-detail.tsx` — renderer, gallery accessibility и mobile safeguards;
- `reports/product-image-ui-verification.md` — этот отчёт.

## Проверка сценариев

### Каталог / карточки

- Сетка: 2 колонки на базовом mobile, 3 на `lg`, 4 на `xl`; контейнер имеет адаптивные боковые отступы.
- Карточка сохраняет квадратную область без layout shift.
- Основное фото больше не обрезается; фон заполняет свободные поля.
- Кнопки избранного и добавления остаются поверх изображения и доступны на mobile.

### Страница товара с одним изображением

- Для #3 выводится главное изображение.
- Лента миниатюр закономерно отсутствует (`images.length === 1`).
- На узком viewport контент идёт одной колонкой; с `lg` — двумя.

### Страница товара с несколькими изображениями

- Для #2 формируются 10 кнопок миниатюр.
- Нажатие меняет индекс главного изображения; выбранная кнопка обозначается ring и `aria-pressed`.
- Лента имеет `overflow-x-auto`, поэтому 10 изображений не расширяют mobile viewport.

### Ошибки и fallback

- Текущий каталог не содержит пустых или отсутствующих файлов.
- Если путь отсутствует или загрузка завершается ошибкой, renderer заменяет сломанное изображение нейтральным fallback, не меняя каталог и не подставляя чужой контент.

## Оставшиеся риски

- Без установленного браузерного E2E-инструмента не выполнена автоматическая визуальная/пиксельная проверка на конкретных размерах, например 320×568, 390×844, 768×1024 и 1440×900. Responsive-проверка основана на коде, production HTML и успешной сборке.
- Fallback проверен по ветвям компонента и факту 404; его финальный отрисованный вид не подтверждён screenshot-тестом.
- `object-contain` исключает потерю краёв товара, но может оставлять поля вокруг вертикальных/горизонтальных кадров — это ожидаемый компромисс в пользу полноты товара.
- Миниатюры всё ещё используют `object-cover`; небольшое кадрирование допустимо для навигации, главное изображение показывает полный кадр.
- Право использования и визуальные водяные знаки остаются за пределами UI-проверки; соответствующие ограничения документированы в `reports/product-image-sources.md`.
- Lint заблокирован устаревшим npm-script `next lint`; для полноценного lint-gate требуется отдельная миграция конфигурации ESLint.
